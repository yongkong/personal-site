## 背景

这个[课程站](https://yongkong.github.io/learn-mattpocock-skills/)教的是 Matt Pocock 的 agent skills（25 个技能，五章）。它本身就是这套技能的实战案例：我没有先学完再动手，而是边用边学——9 月 18 日按 `/setup-matt-pocock-skills` 把仓库配好，同一天跑完第一轮主流程，20 日收尾。三天。课程教什么，仓库的 issue 历史就真实走过什么，可以逐条点开对照。

## 我的角色

一个人，两个身份。学员身份有测验成绩、薄弱簇归因和处方，逐日写进 learning-records/，共 10 篇；操作员身份负责跑流水线，把站点从想法变成上线产品。两个身份共用同一份证据：GitHub Issues #1–#24，一票一个 commit，`git log` 里按 `feat: 工单 #N` 可检索。

## 技术决策

主流程 `grill → spec → tickets → implement → code-review`（implement 内部驱动 /tdd 一次一个红绿切片）完整跑了三轮：课程首页（#1 spec → #2/#3 工单）、词典（#4 spec → #5/#6 工单）、公开课站改造（#12 spec → #13–#24 共 12 张工单，带 blocked-by 依赖边，当天落了 9 张）。每张工单开一个全新会话执行，做完即清上下文。

三张 spec 之外，#7 是另一种票。把教学工作区改造成公开课站，受众、信息架构、语域、载体一条都拍不下来，雾大到单次会话装不下，于是用 /wayfinder 铺图：#8/#9 两张 research 票交给后台子代理并行跑；#10/#11 两张决策票由我逐题拍板——第一次对 AI 的方案说了不（导航体验、语域书面化），这两条异议直接改了地图的形状。拍板前 /prototype 出过 A/B/C 三版首页原型，「答题实验」的结果就是 #10 的全部内容。地图走清当天，/to-spec 写出 #12，/to-tickets 拆出 12 张工单。

载体决议被推翻过一次：#7 定的是纯静态 + GitHub Pages，#12 写 spec 时升级成 Next.js + shadcn/ui + Vercel，修订有存档。地图管方向，不管死守。

技术栈本身没什么好说的：Next.js + TypeScript + MDX，静态导出，构建期校验 frontmatter。值得一提的是测试接缝——「完成」由机器对着渲染后的静态产物判定，不靠自觉。

上线在第 2 天，当天连排三障：Vercel 导入没设 Root Directory，构建失败；静态导出的 RSC 预取打 404，全站 Link 关掉 prefetch；续学按钮 hydration 失配，改成两段式默认值。排障期发过一次性 Vercel token，用 /wizard 生成四阶段脚本（定位 → 核对 → y/N 门删除 → 验证）走完生命周期即弃。随后 /improve-codebase-architecture 跑了首轮架构评审，六项改进落地，顺手修掉一个存量真 bug：MDX 管线一直没开 GFM，前四课的表格全渲染成竖线。

最巧的是闭环。学到 wayfinder 那一课时，这张地图正在为这个站点铺开；上线后的 bug 和架构债，反过来成了 Upkeep 章节的现成素材——课件内容就是从站点的真实决策里长出来的。三天之后流程没停：间隔重测继续出数据（0007–0010），薄弱簇从「纪律性禁区」升级归因为「旧直觉压过新规则」，出题开始显式加变式。

完整复盘在仓库里，三层证据全部可点开：[docs/journey.md](https://github.com/yongkong/learn-mattpocock-skills/blob/main/docs/journey.md)（时间线与技能→证据对照）、[Issues #1–#24](https://github.com/yongkong/learn-mattpocock-skills/issues)、[learning-records/](https://github.com/yongkong/learn-mattpocock-skills/tree/main/learning-records)。关于这套工作流的主张应该可审计，而不是可向往——这三层留痕就是审计入口。
